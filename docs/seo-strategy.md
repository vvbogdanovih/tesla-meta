## 2. Рівень 1 — Міграція без втрат (критично)

### 2.1 URL і редиректи

> **⚠️ УВАГА — потребує підтвердження.** За попередніми даними чинний `teslalviv.com`, ймовірно, **майже або зовсім не проіндексований** (реклама не запускалась; `site:teslalviv.com` не дає результатів). Якщо це підтвердиться в **Google Search Console (Coverage)** — наявної органічної цінності немає, тож:
> - ризик втрати позицій (G4) практично **нульовий**;
> - карта 301 стає **необов'язковою** (потрібна лише для тих URL, що *встигли* проіндексуватися, якщо такі є);
> - ми вільні одразу закласти найчистішу структуру URL **без редиректної тривоги**.
>
> **Дія до фіналізації:** перевірити індексацію в GSC. Доки не підтверджено — рішення про редиректи [ADR-0001](adr/0001-url-structure-and-redirects.md) у статусі *Proposed*. Також уточнити, який домен канонічний (`teslalviv.com` vs наявний `teslalviv.com.ua`).

**Рішення ([ADR-0001](adr/0001-url-structure-and-redirects.md), Proposed):** нові чисті URL. Карта 301 — **лише якщо** виявиться проіндексований контент.

| Тип | Чинний URL | Новий URL |
|-----|-----------|-----------|
| Категорія (модель) | `/product-category/model-3/` | `/category/model-3` |
| Підкатегорія (система) | `/product-category/model-3/kuzov-model-3/` | `/category/model-3/kuzov` |
| Товар | `/product/[slug]/` | `/product/[slug]` *(slug зберігаємо)* |
| Highland / Juniper | `/product-category/model-3-jan-2024/` · `…model-y-feb-2025/` | `/category/model-3-highland` · `/category/model-y-juniper` |

Правила:
- **301 (permanent)** для кожного старого URL → новий. Жодних 302, жодних ланцюгів редиректів.
- Джерело істини для повного списку — чинні `product-sitemap.xml` + `product_cat-sitemap.xml` + `page-sitemap.xml` (експортувати на старті).
- Slug-и товарів **не міняти** (там часто артикул/назва — це SEO-актив).
- Прибрати trailing slash консистентно (обрати один варіант і дотримуватись; редирект з іншого).
- Карта редиректів — як версійований файл у репо коду (напр. `redirects.config`), не «в голові».

### 2.2 Паритет on-page (мінімум 1:1, бажано краще)

Для кожного типу сторінки перенести й не погіршити:
- `<title>` та meta `description` (унікальні на сторінку);
- `<link rel="canonical">` (самопосилання для індексованих);
- Open Graph + Twitter Card (title, description, image з розмірами, locale, url, type);
- H1 та структуру заголовків.

### 2.3 Паритет structured data (JSON-LD)

Відтворити **весь** наявний schema і розширити:

| Schema | Сторінка | Поля |
|--------|----------|------|
| `Product` + `Offer` + `PriceSpecification` | картка товару | name, sku, image, brand, price, priceCurrency, availability, **aggregateRating** (якщо з'являться відгуки) |
| `BreadcrumbList` | усі вкладені | повний шлях категорія → підкатегорія → товар |
| `Organization` | наскрізно | name, logo, contactPoint, sameAs (соцмережі) |
| `WebSite` + `SearchAction` | головна | sitelinks searchbox |
| `ItemList` | категорії | список товарів *(нове, підсилює категорійні сторінки)* |
| `BlogPosting` | статті | headline, author, datePublished, image |

### 2.4 Технічні артефакти

- `sitemap.xml` — індекс із окремими sitemap для товарів, категорій, сторінок, блогу + актуальний `lastmod`; авто-генерація при зміні даних.
- `robots.txt` — закрити `/cart`, `/checkout`, `/account`, `/search`, службові; дозволити каталог; вказати sitemap.
- HTTPS, той самий домен, HSTS.
- Кастомна 404 з пошуком і посиланнями на популярні категорії.

### 2.5 Чеклист запуску (SEO acceptance)

- [ ] Карта 301 покриває 100% URL зі старих sitemap; перевірено скриптом (0 помилок/ланцюгів).
- [ ] Усі товари/категорії віддають 200 + повний HTML (SSR/ISR), не порожній клієнтський каркас.
- [ ] `title`/`description`/`canonical`/OG/JSON-LD присутні й валідні (Rich Results Test).
- [ ] Новий `sitemap.xml` згенеровано й надіслано в GSC.
- [ ] GSC: домен підтверджено, стара/нова версія, моніторинг 404 і Coverage.
- [ ] Перенаправлення перевірено вручну на топ-50 сторінок за трафіком.
- [ ] Lighthouse SEO ≥ 95 на головній, категорії, картці.

## 3. Рівень 2 — Технічний фундамент (переваги над WordPress)

- **SSR/ISR** для всіх індексованих сторінок — бот отримує повний HTML. CSR лише для приватних (кошик, кабінет, checkout).
- **Core Web Vitals** — головна перевага над WP+плагінами:
  - LCP < 2.5с (next/image, пріоритет hero, S3/CDN, webp/avif, розміри зображень);
  - CLS ~0 (зарезервований простір під медіа);
  - INP — мінімум важкого JS на каталозі.
- **Пагінація:** self-canonical на кожній сторінці (`?page=2` канонічний сам на себе, не на 1-шу); `rel=prev/next` не обов'язковий, але логічна перелінковка має бути.
- **Hreflang-готовність:** архітектура під майбутню багатомовність (зараз лише `uk`), щоб додати без переробки URL.

## 4. Рівень 3 — Приріст (обігнати конкурентів)

### 4.1 Фасетні фільтри — гібридна індексація

**Рішення:** індексуємо цінні комбінації, решту закриваємо. Це дає тисячі long-tail сторінок без краулінг-сміття.

| Фасет / комбінація | Індексація | URL |
|--------------------|-----------|-----|
| Категорія (модель) | **index**, self-canonical, у sitemap | чистий шлях |
| Підкатегорія (модель + система) | **index**, self-canonical, у sitemap | чистий шлях |
| Тип: оригінал / аналог (в межах категорії) | **index** (цінний запит) | чистий шлях, напр. `/category/model-3/kuzov/original` |
| Стан: новий | noindex (майже все «нове») | query-параметр |
| Наявність (inStock) | **noindex, follow** | query-параметр |
| Діапазон ціни | **noindex, follow** | query-параметр |
| Сортування (orderby) | **noindex** + canonical на базову | query-параметр |
| 2+ фасети одночасно | **noindex, follow** | query-параметри |

Правила:
- Індексовані фасети → **чистий шлях** + self-canonical + запис у sitemap + унікальні title/H1.
- Неіндексовані → **query-параметри** (`?inStock=true&minPrice=…`), `noindex,follow`, canonical на чисту базову сторінку.
- У `robots.txt` **не** блокувати фасети-параметри (хай бот бачить `noindex` і не вважає їх «зниклими»); керувати індексацією через meta-тег, а не Disallow.

**Поточна реалізація (`/shop`):** чистих категорійних шляхів (`/category/...`) у коді ще немає — категорія передається query-параметром `?category=`. Тому зараз: базова `/shop` і `/shop?category=x` → **index**, canonical на відповідну базу; будь-який інший фасет (`car`, `sort`, `inStock`, `minPrice/maxPrice`, `type`, `condition`, `page>1`) → **noindex,follow** + canonical на базу. Перехід на чисті ЧПУ категорій — окрема задача (ADR-0001), після якої canonical переведемо на чистий шлях.

### 4.1b Прайс-лист (`/price-sheet`, ADR-0011)

`/price-sheet` — табличний вигляд того самого каталогу (`GET /catalog/products`), ризик дубль-контенту з `/shop`. Рішення (ADR-0011 «власне SEO»):

- **База `/price-sheet`** (без параметрів) → **index, self-canonical**, у sitemap. Окремі `title`/`H1` під інтент «прайс-лист / price list» + вступний абзац — щоб не був тонким дублем `/shop`.
- **Будь-який фасет-параметр** (`q`, `category`, `car`, `type`, `condition`, `inStock`, `minPrice/maxPrice`, `sort`) → **noindex,follow**, canonical на базову `/price-sheet`.
- Отже — **рівно одна індексована** price-sheet-URL; категорійні/фасетні index-сторінки належать `/shop`, price-sheet їх не дублює. Пагінаційного `?page` немає (нескінченний скрол).

`/wishlist` — **noindex** (приватний сигнал інтересу, ADR-0012).

### 4.2 Контент і запити

- **Оптимізація під артикул/OEM** (напр. `1645989-00-A`) — користувачі шукають коди; картка має ранжуватися по SKU (sku в `<title>`/H1/schema/тексті).
- **SEO-тексти на лендингах** категорій і ключових підкатегорій (унікальний опис 150–300 слів, без переспаму).
- **Блог** під інформаційні запити: «як замінити …», «який артикул на …», «оригінал чи аналог …» — із перелінковкою на товари.
- **Внутрішня перелінковка:** хлібні крихти, «схожі товари», крос-лінки між системами однієї моделі, «той самий товар для іншої моделі».
- **Зображення:** змістовні `alt` з назвою+моделлю+артикулом; імена файлів; image sitemap опційно.

### 4.3 Off-page (поза кодом, для повноти)

- Google Business Profile (Львів), консистентні NAP.
- Беклінки: Tesla-спільноти, форуми, профільні майданчики.
- Відгуки (якщо впровадимо) → `aggregateRating` у schema → зірочки у видачі.
