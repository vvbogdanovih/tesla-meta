> Цей документ — дизайн-напрям нового сайту: візуальна мова, теми, типографіка, рух і правила, що балансують «вау» з продуктивністю (CWV) та головним завданням — швидко знайти деталь (PRD G2).

## 0. Головний принцип

**Чистота + швидкість + точковий рух.** Це магазин запчастин, а не промо-лендинг: інтерфейс служить сценарію «модель → система → фільтр → картка → кошик» (≤ 60 сек до товару). Естетика преміальна й сучасна, але ніколи не коштом findability чи Core Web Vitals.

---

## 1. Візуальна мова — «Tesla Minimal»

- **Стримана база + теплий акцент (НЕ ЧБ):** холодно-сіра нейтральна база + один фірмовий акцент — **Golden Amber**. Колір працює прицільно (CTA, активні стани, ключові акценти), а не заливає екран. Повна палітра — у §2.1.
- **Багато повітря:** щедрі відступи, дихання між блоками, великі клік-зони.
- **Велика типографіка:** виразні заголовки, чітка ієрархія.
- **Великі продуктові фото** як головний візуальний герой (фото деталі продає).
- **Мінімум декору:** жодних зайвих рамок, тіней-нагромаджень, градієнтного шуму.

Орієнтир — естетика самої Tesla (tesla.com): стримано, преміально, впевнено.

### Застосування по типах сторінок

| Зона | Підхід |
|------|--------|
| Головна, картка товару, контент (про нас, блог) | **Minimal-режим:** великі фото, повітря, акцент на емоції/бренд |
| Каталог (категорія, підкатегорія, пошук) | **Functional-режим:** щільніша сітка, фільтри попереду, максимум usability/конверсії |

> Тобто єдина візуальна мова, але каталог свідомо щільніший — це робоча конячка конверсії.

## 2. Теми (світла + темна)

- **Світла за замовчуванням**, темна — через перемикач; вибір зберігати (localStorage) + поважати `prefers-color-scheme`.
- Реалізація через **design tokens** (CSS-змінні): кольори, типографіка, відступи, радіуси, тіні, тривалості анімацій — щоб теми й бренд правились централізовано.
- **Фото товарів** показувати на нейтральному/світлому тлі навіть у темній темі (читабельність деталі важливіша за «суцільну темність»).
- Контраст обох тем — не нижче **WCAG 2.1 AA** (NFR-5).

## 3. Типографіка, сітка та контейнер

### Типографіка

Дві гарнітури: **Unbounded** (лише hero/display) + **Onest** (заголовки секцій і весь текст). Обидві — відмінна кирилиця.

| Роль | Шрифт | Вага | Приклад |
|------|-------|------|---------|
| Display / Hero H1 | **Unbounded** | 500 Medium | «Знайди потрібну деталь за хвилину» |
| Heading H2 | **Onest** | 700 | «Каталог запчастин Tesla» |
| Heading H3 | **Onest** | 600 | «Model 3 · Кузов» |
| Body | **Onest** | 400 | основний текст |
| Small / підписи | **Onest** | 500 | характеристики, примітки |
| Акценти (ціна, кнопки, бейджі) | **Onest** | 700–800 | «1 150 ₴» |
| Артикул / код | **ui-monospace** | 400 | `1645989-00-A` |

Правила:
- **Unbounded — тільки великі display-моменти (hero).** Не для секційних заголовків чи тексту: у бізнес-контексті виглядає надто дисплейно.
- **Великі заголовки — легша вага** (Unbounded 500); дрібні акценти — жирніші (700–800). Великі заголовки на 800 «давлять» — уникати.
- **Onest** — єдиний бізнес-гротеск для всього контенту: чистий, нейтральний, серйозний.
- **Артикули/коди** — моноширинним (`ui-monospace`) для читабельності.
- `font-display: swap`, сабсет кирилиці, прелоад критичних; межа довжини рядка для читабельності.
- **Fallback-стек:** Unbounded → `system-ui, sans-serif`; Onest → `-apple-system, "Segoe UI", Roboto, sans-serif`.
- Spacing-scale на базі токенів (крок 4/8 px).

### Контейнер і ширина (full-bleed фон + constrained контент)

**Принцип:** фони/смуги тягнуться на всю ширину viewport, **вміст завжди в центрованому контейнері з max-width**. Це прибирає «розповзання» на широких екранах і вирівнює всі блоки по єдиній сітці.

| Токен | Значення | Застосування |
|-------|----------|--------------|
| `--container` | **1240px** | контент, hero-текст, **вміст хедера**, секції |
| `--container-wide` | **1440px** (опційно) | каталог (фільтри + сітка), якщо потрібна щільніша сітка |
| `--gutter` | **24px** desktop / **16px** mobile | бокові відступи контейнера |

Правила:
- **Хедер:** підкладка + нижня лінія — на всю ширину (sticky від краю до краю); лого/меню/пошук/іконки — у `--container`, вирівняні з контентом нижче.
- **Hero:** фон/зображення — full-bleed; заголовок, текст і CTA — у `--container` (вирівняні з рештою).
- **Каталог та всі контентні секції:** у контейнері. Без обмеження сітка карток розтягується нечитабельно на 1920/2560px.
- **Кольорові секції/банери:** фон full-bleed, вміст у контейнері (патерн «band → container»).

### Сітка
- 12 колонок усередині контейнера, консистентні breakpoints, **mobile-first** (NFR-4).

## 4. Рух та анімації

**Рівень: імерсивно, але в межах бюджету продуктивності.** Рух підкреслює якість, не заважає й не гальмує.

### Правила (тверді)

1. **Hero легкий:** паралакс лише через `transform`/`opacity` (GPU-friendly), **без 3D на першому екрані**. Перший екран — пріоритет LCP.
2. **Важкі ефекти — lazy:** 3D-сцени, складний scroll-driven, важкі Lottie — підвантажувати **нижче згину** / по взаємодії, ніколи не блокувати перший рендер.
3. **`prefers-reduced-motion: reduce`** — обов'язково: вимикати нетривіальний рух. Це і доступність (NFR-5), і добра практика для Google.
4. **Без CLS:** анімації не зсувають контент; резервувати простір під медіа/банери.
5. **INP-safe:** анімувати лише `transform`/`opacity`; жодних layout-thrash властивостей (`top/left/width/height`) в рантаймі.
6. **Швидко:** мікро-взаємодії 120–250 мс; великі переходи ≤ 400 мс. Природний easing.

### Що робимо (дешеве й ефектне)

- Мікро-взаємодії: hover на картках товару, стани кнопок, анімований лічильник кошика.
- **Skeleton-loading** замість спінерів на каталозі/картці.
- **Scroll-reveal** появи блоків (IntersectionObserver, легко).
- **Page-transitions** — Next.js **View Transitions API**.
- Плавне відкриття модалок («швидкий перегляд», «Купити в 1 клік»), drawer кошика/фільтрів.
- Легкий паралакс фонових зображень на hero (через `transform`).

### Чого уникаємо на першому екрані

- Відео-фони, важкі 3D (Three.js), повноекранний паралакс, анімації що блокують взаємодію.

## 5. Ключові компоненти (напрям)

- **Hero (головна):** кінематографічна сцена — темна full-bleed підкладка з бурштиновим світінням і технічною сіткою; **фото Tesla праворуч, що «виринає» з темряви** (ліва частина фото розчиняється в фон через mask-градієнт + scrim, щоб текст ліворуч лишався читабельним). Зліва: eyebrow, великий заголовок, інтегрований пошук (назва/артикул), CTA, картки моделей із кількістю деталей, стат-стрічка. Рух — поява + легкий parallax (через `transform`, з повагою до `prefers-reduced-motion`). Без відео/3D на першому екрані (бюджет LCP). Тема hero — темна в обох режимах сайту (свідомий акцент).
- **Картка товару (грід):** велике фото, назва, артикул, бейджі (Новий/Оригінал/Аналог), ціна (стара/нова), швидке «в кошик» на hover. Зберегти все, що вже є на сайті, але візуально підняти.
- **Картка товару (сторінка):** велика галерея з зумом/лайтбоксом, чіткі бейджі, таблиця характеристик, accordion (гарантія/доставка), «Схожі товари».
- **Фільтри:** sticky-сайдбар (desktop) / drawer (mobile); миттєвий відгук, лічильники, активні фільтри як «чіпи», стан в URL (SEO — див. [seo-strategy §4.1](seo-strategy.md#41-фасетні-фільтри--гібридна-індексація)).
- **Пошук:** помітний у хедері, з автодоповненням (назва + артикул), дропдаун топ-результатів.
- **Хедер:** лаконічний, sticky; логотип, меню, пошук, кошик, перемикач теми, бургер на mobile.
- **Кнопки/інпути/бейджі:** єдина система станів (hover/active/focus/disabled), видимий focus-ring (доступність).

## 6. Бюджет продуктивності (зв'язок із SEO)

Дизайн зобов'язаний триматись у межах ([NFR-1](FRD.md), [SEO-3](seo-strategy.md)):
- **LCP < 2.5с**, CLS ~0, INP у зеленій зоні; CWV «Good» для 75%+ сторінок.
- Зображення: `next/image`, S3/CDN, webp/avif, явні розміри, пріоритет hero.
- Шрифти: `font-display: swap`, сабсет кирилиці, прелоад критичних.
- JS анімацій: code-split, lazy; бібліотека руху (напр. Framer Motion) — лише де треба, не глобально.
- **Перевірка:** кожен «вау»-ефект проходить тест на CWV перед релізом; не вписався в бюджет — спрощуємо.

---

## 7. Доступність (NFR-5, WCAG 2.1 AA)

- Контраст ≥ AA в обох темах; видимий фокус; повна навігація з клавіатури.
- `prefers-reduced-motion` поважається скрізь.
- Семантична розмітка, `alt` для фото (з назвою/моделлю/артикулом — ще й SEO-бонус), ARIA для модалок/дропдаунів/фільтрів.

## 8. Відкриті питання (дизайн)

1. Чи є **бренд-гайд / лого / фірмові кольори** Tesla Lviv, чи створюємо айдентику з нуля?
2. Хто робить **макети** (Figma) і чи потрібен повний UI-kit / дизайн-система до старту розробки?
3. Чи потрібен акцентний колір поверх монохрому (напр. для CTA/знижок), чи тримаємось суто Tesla-палітри?
4. Джерело **якісних фото товарів** — поточні фото достатньої якості для «великих» карток, чи потрібна пересʼйомка?
5. Чи робимо повноцінний **прототип головної+каталогу+картки** для узгодження до коду?
6. **Ліцензія на hero-фото Tesla.** У макеті використано стороннє прес-фото (rbk.ru) лише для прев'ю — для продакшену потрібне легальне джерело: офіційний прес-кіт Tesla (media.tesla.com), ліцензійний сток (Shutterstock/Getty), власна зйомка або згенероване зображення під ліцензію.
