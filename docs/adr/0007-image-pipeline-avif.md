# ADR-0007: Завантаження й конвертація зображень — AVIF на бекенді

- **Статус:** Accepted
- **Дата:** 29.06.2026
- **Автори:** команда проєкту
- **Пов'язано:** [backend-architecture.md](../backend-architecture.md) · [ADR-0006](0006-rich-text-tiptap-json-html.md)

## Контекст

Каталогу потрібні зображення товарів/авто з оптимальними розміром і якістю (Core Web Vitals — SEO-пріоритет). Спершу був presigned-аплоад напряму в R2 (браузер → PUT), але це зберігало оригінали без оптимізації та без контролю формату. Завантаження роблять **лише адміни і зрідка**, тож головний плюс presign (розвантаження трафіку сервера) тут неважливий.

## Рішення

**Конвертація на бекенді через `sharp`** (libvips). Файл проксується через NestJS, а не вантажиться напряму в сховище.

- Ендпоінт `POST /s3/upload` (multipart, лише admin/superadmin): `sharp` робить авто-орієнтацію за EXIF → ресайз до 1600px (`fit: inside`, без збільшення) → кодує у **AVIF** (`quality 55`) → кладе в R2 з `Cache-Control: immutable` (імена з UUID) → повертає `{ key, url }`.
- Ліміт 10 MB, валідація типу (`jpeg|png|webp|avif|gif`).
- Галерея товару: кілька зображень, порядок — поле `sortOrder`; на адмінці drag-and-drop (`@dnd-kit`).
- Presigned-аплоад (`/s3/presign`) лишається опцією для прямого завантаження без обробки.

## Наслідки

- ✅ Детермінована якість і формат (AVIF — на ~20–30% менший за WebP), стрипання метаданих, єдина точка обробки + валідація на сервері.
- ✅ Контроль розміру (ресайз) і вічний кеш на CDN.
- ⚠️ Байти йдуть через VPS (CPU+трафік) — прийнятно для адмінських нечастих завантажень.
- ⚠️ AVIF не показують ~5% старих браузерів (Safari <16). Якщо стане проблемою — `<picture>` з webp-фолбеком або трансформації на доставці (Cloudflare `format=auto`), зберігаючи оригінал.
