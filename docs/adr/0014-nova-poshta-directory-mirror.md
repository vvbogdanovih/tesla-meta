# ADR-0014: Nova Poshta — дзеркало довідника в БД + синхронізація (cron + кнопка)

- **Статус:** Accepted
- **Дата:** 02.07.2026
- **Автори:** —

## Контекст

У чекауті потрібні автопідказки міст і **відділень / поштоматів** Нової Пошти при вводі. Довідник великий (~30k міст, ~40k+ відділень і поштоматів) і змінюється повільно. Бити АПІ Пошти на кожен ввід користувача — неприйнятно (ліміти, латентність, залежність від доступності NP). Токен `NOVA_POSHTA_API_KEY` серверний — на клієнт його виносити не можна.

## Розглянуті варіанти

- **A. Live-проксі на кожен запит** (+кеш відповідей із TTL). Просто, але залежить від NP на кожен ввід, ліміти, латентність.
- **B. Дзеркало довідника в нашій БД** (обрано). Періодична синхронізація в таблиці `np_cities` / `np_warehouses`; автопідказки — зі своєї бази (trigram-пошук `pg_trgm`). Швидко, без лімітів, стійко до недоступності NP.

## Рішення

Варіант **B**. 

- Таблиці-дзеркала `NpCity`, `NpWarehouse` (+ trigram-GIN на `name` / `description`), тип відділення — окреме поле `NpWarehouseType { branch | postomat | cargo }` (мапиться з `CategoryOfWarehouse`). У чекауті — перемикач **Відділення / Поштомат**.
- `NpSyncService.run()` — upsert за NP `Ref`, зниклі → `isActive=false`; стан пише в `NpSyncState` (singleton).
- **Два тригери синхронізації, один сервіс:**
  - **cron** `@Cron('0 3 1,15 * *')` (1-го і 15-го о 03:00 ≈ раз на 2 тижні), загейчений `if (ENV.RUN_CRON)` — щоб синхронізував лише один інстанс (прод);
  - **кнопка в адмінці** (superadmin) `POST /api/delivery/np/sync` — завжди. На тесті `RUN_CRON=false`, тож синхронізація — виключно кнопкою.
- Публічні read-ендпоінти зі свого дзеркала: `GET /api/delivery/np/cities?q=`, `GET /api/delivery/np/warehouses?cityRef=&type=&q=` (+ `Cache-Control`, довідник змінюється рідко).
- Токен NP лишається на бекенді; клієнт спілкується лише з нашим API.

## Наслідки

- Позитивні: миттєві автопідказки без навантаження на NP; стійкість до недоступності NP; серверний токен; тип відділення (відділення/поштомат) — першокласний фільтр.
- Негативні / компроміси: ~70k рядків дзеркала й повна синхронізація батчами (нічний cron); первинний bootstrap порожньої БД — ручною кнопкою; дані «застарілі» до 2 тижнів (прийнятно для довідника).
- Що додає у [FRD](../FRD.md): автопідказки доставки в чекауті; розділ **«Системні налаштування»** в адмінці (superadmin) із кнопкою синку. У [db-schema](../db-schema.md) — моделі `NpCity` / `NpWarehouse` / `NpSyncState` + enum. Села (`searchSettlements`) та Укрпошта — поза цим ADR.
