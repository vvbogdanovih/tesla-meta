# ADR-0002: Каталог — довідник авто, M2M-сумісність, глобальні категорії

- **Статус:** Accepted
- **Дата:** 27.06.2026
- **Автори:** команда проєкту

## Контекст

Початкова модель: **категорія = модель авто → підкатегорія = система → товар**, тобто товар «належить» одній моделі. Але багато запчастин (кліпси, кріплення, частина кузовних/електричних деталей, зарядні аксесуари) підходять до **кількох моделей**. У жорсткій ієрархії це змушує або **дублювати товар** під кожну модель (різні записи на той самий артикул → бардак у залишках/цінах і дублі для SEO), або втрачати інформацію про сумісність.

Проблема в тому, що в одному дереві змішано **дві різні сутності**: сумісність із моделями (зв'язок багато-до-багатьох) і категорію (товарна таксономія).

## Рішення

Розділити сумісність і таксономію:

1. **Довідник автомобілів (`cars`)** — окрема нормалізована таблиця на рівні **покоління/фейсліфта**, без текстових назв моделей у картці товару:

   | id | brand | model | generation | production_start | production_end |
   |----|-------|-------|------------|------------------|----------------|
   | 1 | Tesla | Model 3 | Pre-facelift | 2017-07 | 2023-10 |
   | 2 | Tesla | Model 3 | Highland | 2023-10 | null |
   | 3 | Tesla | Model Y | Phase 1 | 2020-01 | 2025-01 |
   | 4 | Tesla | Model Y | Juniper | 2025-02 | null |

2. **Сумісність — M2M** через таблицю `product_fitment` (`product_id` ↔ `car_id`). Товар — **один запис** (один canonical, унікальний `sku`), пов'язаний з усіма сумісними авто.

3. **Категорії (`categories`)** — глобальний спільний довідник (Кузов, Підвіска, Гальмівна система…), один для всіх моделей (без дублів «Кузов Model 3 / Model Y»). Товар має одну категорію (`category_id`).

**Навігація для користувача не змінюється**, але стає **фільтром-в'ю**:
- `/category/model-3` → товари, де `fitment ∋ Model 3`;
- `/category/model-3/kuzov` → ті самі + `category = Кузов`;
- товар живе за єдиним URL `/product/[slug]`.

## Наслідки

- ✅ Немає дублів товарів; залишки/ціни/контент — в одному місці.
- ✅ **Краще SEO:** один canonical на товар замість дублів під кожну модель.
- ✅ Чесна сумісність на картці: «Підходить до: Model 3, Model Y, Highland».
- ✅ Каталог уже використовує модель як **фільтр** — UI майже не змінюється.
- ✅ Готовність до **VIN-підбору** (Фаза 3): VIN → покоління авто → сумісні товари.
- ⚠️ **Міграція:** товари з WooCommerce, розкидані по модельних категоріях, треба **злити в один товар зі списком сумісності** (дедуплікація за артикулом) — додати в план міграції (NFR-3).
