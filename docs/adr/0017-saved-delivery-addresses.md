# ADR-0017: Збережені адреси доставки — лише для авторизованих

- **Статус:** Accepted
- **Дата:** 07.07.2026
- **Автори:** —

## Контекст

Користувач вводить дані відправки (ПІБ, телефон, місто, відділення НП) на кожному оформленні. Це тертя, особливо для повторних покупок. Хочемо покращити UX — дати змогу зберігати й перевикористовувати дані відправки.

Обмеження та передумови:
- Гостьовий checkout дозволений (FR-6.4) — значна частка трафіку не авторизована.
- У схемі вже є модель `Address`, привʼязана до `User` (`label`, `method`, `city`, `warehouse`, `recipient`, `phone`, `isDefault`).
- Доставка НП — combobox-флоу (місто → тип → відділення) з локального дзеркала довідника; у снапшот замовлення пишуться `cityRef`/`warehouseRef`/`warehouseType` для ТТН ([ADR-0014](0014-nova-poshta-directory-mirror.md), FR-6.2a).
- Снапшот `Order.delivery` навмисно незалежний від довідників і від `Address` ([ADR-0013](0013-order-status-method-columns.md)).

## Розглянуті варіанти

- **Варіант A — тільки гість (localStorage):** передзаповнення останніх даних без бекенду. Плюси: працює для гостей, нуль серверної роботи. Мінуси: не синхронізується між пристроями, не дає керування кількома адресами, «магія» localStorage без явної згоди.
- **Варіант B — тільки профіль (`Address`), лише для авторизованих:** повноцінні збережені адреси з CRUD і вибором у checkout. Плюси: явна модель, крос-девайс, керування кількома адресами, стимул до реєстрації. Мінуси: гість вигоди не отримує; треба бекенд-CRUD + UI.
- **Варіант C — обидва рівні одразу:** максимальний UX, але більший обсяг і дублювання логіки (guest localStorage + auth Address) на цьому етапі.

## Рішення

Ухвалено **Варіант B**: збережені адреси доставки — **лише для авторизованих**, на базі наявної моделі `Address`. localStorage-передзаповнення для гостей поки не робимо (можна додати згодом окремим рішенням).

Модель `Address` розширюється НП-референсами, щоб збережена адреса відновлювала combobox і давала майбутній ТТН:
`cityRef`, `warehouseRef`, `warehouseType` (`branch|postomat|cargo`).

UX:
- **Checkout, залогінений, є адреси:** список карток-радіо (default вибрана одразу) + картка «＋ Нова адреса»; вибір заповнює форму.
- **Checkout, залогінений, без адрес:** форма (combobox НП, FR-6.2a) + чекбокс «Зберегти в профіль» (увімкнений; перша збережена стає `isDefault`).
- **Checkout, гість:** звичайна форма без збереження + м'який нудж «Увійдіть, щоб зберегти адресу» (не блокує оформлення).
- **Профіль → «Адреси доставки»:** CRUD (додати / редагувати / видалити / зробити основною).

Снапшот `Order.delivery` формується з обраної адреси на момент оформлення й лишається незалежним — видалення чи зміна `Address` не впливає на існуючі замовлення.

## Наслідки

- Позитивні: менше тертя для повторних покупок; крос-девайс; стимул до реєстрації; готовність до ТТН завдяки збереженим НП-референсам.
- Негативні / компроміси: гість вигоди не отримує (свідомо відкладено); потрібен бекенд-CRUD `Address` + UI в checkout і профілі.
- Зміни в [FRD](../FRD.md): нові **FR-6.4a** (збережені адреси в checkout) та уточнено **FR-7.2** (розділ профілю з CRUD). Зміни в [db-schema](../db-schema.md): `Address` + `cityRef`/`warehouseRef`/`warehouseType` (потрібна міграція).
