# ADR-0011: Price-sheet — табличний вигляд каталогу

- **Статус:** Accepted
- **Дата:** 01.07.2026
- **Автори:** команда проєкту
- **Пов'язано:** [ADR-0002](0002-catalog-compatibility-architecture.md) (каталог/сумісність) · [FRD §3.3a (FR-2.8–2.13)](../FRD.md) · [db-schema.md](../db-schema.md)

## Контекст

Крім сітки карток (`/shop`), потрібен **прайс-лист** — щільний табличний перегляд каталогу (референс: `fillando.com/price-sheet`). Табличний вигляд зручний для B2B-перегляду, швидкого сканування артикулів/цін/наявності та підбору за сумісністю без переходу в кожну картку.

Ключові обмеження:

- Каталог — **єдиний канонічний запис товару** (ADR-0002); модель авто — фільтр сумісності через M2M `product_fitment`, не таксономія.
- Бекенд-ендпоінт `GET /catalog/products` **вже** підтримує всі фасетні фільтри, сортування та пагінацію.
- У відповіді **списку** немає переліку сумісних авто (`fitment`) — він є лише в картці `/catalog/products/:slug`. Для колонки «Сумісність» його треба додати.

## Розглянуті варіанти

- **A. Окрема сторінка `/price-sheet` + той самий ендпоінт `GET /catalog/products`.** Мінімум дублювання даних і коду; консистентно з ADR-0002. Потрібно лише опційно віддавати `fitment` у списку.
- **B. Перемикач вигляду на `/shop` (`?view=table`).** Один маршрут, але змішує дві дуже різні верстки й ускладнює SSR/кеш; складніше для окремого SEO/посилань.
- **C. Окремий ендпоінт `/catalog/price-sheet`.** Дублює логіку фільтрів/пагінації існуючого списку — зайве.

## Рішення

**Варіант A.** Price-sheet — **окрема публічна сторінка `/price-sheet`** поруч зі сіткою карток (`/shop`), що споживає **той самий** `GET /catalog/products`.

- **Дані:** той самий ендпоінт із параметром **`include=fitment`** — вмикає компактний перелік сумісних моделей у кожному рядку (карткам не потрібно, тому за замовчуванням вимкнено, щоб не роздувати відповідь). Формат: масив унікальних моделей, напр. `["Model 3", "Model Y"]`.
- **Фільтри:** ті самі фасетні фільтри, що й у каталозі (авто, категорія, тип, стан, ціна, наявність) + текстовий пошук; стан фільтрів — в URL (shareable, SSR-friendly).
- **Колонки:** Фото · Назва (+ індикатор наявності) · Артикул · Категорія · Сумісність · Тип · Стан · Ціна (+ стара, якщо `onSale`) · Наявність (`stockQty`) · дія «У кошик».
- **Пагінація:** нескінченний скрол (`IntersectionObserver`, `limit=50`), а не нумерована — оптимально для щільного прайсу.
- **Сортування за замовчуванням:** спочатку в наявності (`stockQty > 0`), далі за назвою; доступний той самий сорт-дропдаун, що й у каталозі.
- **Респонсив:** таблиця на десктопі (sticky-заголовок), картковий список на мобільному.
- **Кошик:** додавання по рядку через наявний `useCartStore` (компактний варіант `AddToCart`).

Колонки виробник/матеріал/колір із референсу Fillando **не переносимо** (специфіка філаменту для 3D-друку). Колонку «Синхронізовано» **не переносимо** — у Tesla немає зовнішньої синхронізації.

## Наслідки

- ✅ Нуль дублювання даних: один товар — один запис — один ендпоінт (узгоджено з ADR-0002).
- ✅ Переюз готового: фільтри, `useCartStore`/`AddToCart`, `catalogApi`, типи, дизайн-токени.
- ✅ Окремий URL — власне SEO та шейрабельні посилання з фільтрами.
- ⚠️ Бекенд: розширити `CARD_SELECT` fitment-ом під прапорцем `include=fitment` + маппінг у масив моделей.
- ⚠️ Фронтенд: винести `CatalogFilters` у переюзабельний компонент (зараз прив'язаний до `/shop`).
- 🔜 Лічильники фасетів (`/catalog/facets`) — окрема ітерація, не блокують запуск (їх зараз немає й у каталозі).
