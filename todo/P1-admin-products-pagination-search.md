# Список товарів в адмінці без пагінації та пошуку

- **Пріоритет:** P1 — критичний (юзабіліті адмінки)
- **Репозиторій:** tesla-admin (+ tesla-backend)
- **Статус:** TODO

## Проблема

Список товарів тягне весь каталог одним запитом, без пошуку за SKU/назвою. Для магазину запчастин із сотнями позицій адмінка стане непридатною для щоденної роботи. Аналогічно: сторінки лідів і wishlist ігнорують пагінацію — wishlist-відповідь має `total/page/pages`, але UI викликає `adminList()` без параметрів, записи поза першою сторінкою невидимі без жодного індикатора.

## Де в коді

- `src/app/(dashboard)/products/page.tsx:17-20` + `products.api.ts` — `list: () => get<ProductListItem[]>` без параметрів
- `src/app/(dashboard)/wishlist/page.tsx:24` — ігнорує `page/pages`
- `src/app/(dashboard)/leads/page.tsx` — список без пагінації

## Що зробити

1. Бекенд: пагінація + пошук на admin `GET /products` (патерн уже є в `catalog.service.ts:84-93`).
2. Адмінка: пагінація + пошук за SKU/назвою у товарах; підключити наявні `page/pages` у wishlist і лідах.
