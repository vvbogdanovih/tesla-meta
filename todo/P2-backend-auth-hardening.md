# Auth: refresh не інвалідовується, роль у JWT не звіряється з БД, слабкий пароль

- **Пріоритет:** P2 — важливий (безпека)
- **Репозиторій:** tesla-backend
- **Статус:** TODO

## Проблема

1. **Logout не інвалідовує refresh-токен**: refresh stateless (лише перевірка підпису) — викрадений токен валідний до експірації; немає ні jti-blacklist, ні ротації з детекцією повторного використання.
2. **Роль у JWT живе до експірації**: `validate()` повертає payload без звірки з БД — розжалуваний/видалений адмін зберігає доступ до кінця дії access-токена.
3. **Пароль від 6 символів**: слабка політика для акаунтів, з яких видно замовлення.

## Де в коді

- `src/modules/auth/auth.service.ts:47-63` — stateless refresh
- `src/modules/auth/strategies/jwt.strategy.ts:17-19` — validate без БД
- `src/modules/auth/dto/register.dto.ts:8-9` — `MinLength(6)`

## Що зробити

1. Ротація refresh-токенів зі збереженням jti (або хешу) у БД + інвалідація при logout і детекція повторного використання.
2. Для admin/superadmin-роутів — звіряти роль із БД у `validate()` (або короткий TTL access-токена + перевірка існування користувача).
3. Підняти мінімальну довжину пароля до 8+.
