# Немає механізму 301-редиректів зі старих URL

- **Пріоритет:** P1 — умовний (блокер, ЯКЩО GSC підтвердить індексацію старого сайту)
- **Репозиторій:** tesla-frontend (+ tesla-backend для наповнення `Redirect`)
- **Статус:** TODO / заблоковано перевіркою Google Search Console (ADR-0001 у статусі *Proposed*)

## Проблема

Модель `Redirect` існує у схемі, але механізму 301 немає ніде:
- немає API/сервісу наповнення `Redirect` на бекенді;
- немає `middleware.ts` чи `redirects()` у `next.config.ts` на фронті;
- немає lookup-механізму віддачі 301.

Runbook §5 визнає: «API та middleware віддачі 301 ще немає». ADR-0001 заблоковано вибором варіанту B vs C залежно від того, чи проіндексований старий контент (реклама/індексація не запускались).

NFR-3 та SEO — критичний пріоритет проєкту; втрата редіректів = втрата SEO-паритету при міграції.

## Що зробити

1. **Спершу** — перевірити Google Search Console: чи є проіндексовані WooCommerce-URL. Це закриває залежність ADR-0001 (варіант B чи C).
2. Якщо є індексація — реалізувати:
   - наповнення `Redirect` під час міграції ([P1-migration-etl-script](P1-migration-etl-script.md));
   - `middleware.ts` (або `next.config.ts redirects()`) для віддачі 301 зі старих URL;
   - версіонований файл карти редіректів (seo-strategy.md §2.2/§3).
3. Пов'язано з [P2-seo-gaps](P2-seo-gaps.md) (ЧПУ-роути категорій `/category/*`).
